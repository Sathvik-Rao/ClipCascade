# Android ClipCascade signaling recovery (10 October 2026)

## Repro and root causes

The Samsung Galaxy S25 app showed `✅ Connected` / `📊 Peers: 0` while Nox had only the Glass websocket peer. Tapping Stop then Start recovered `Peers: 1`, but a transient handshake returned `Expected HTTP 101 response but was '200 OK'` before reauthentication succeeded. The old APK was also a **debug build** repeatedly trying to attach to `localhost:8081` Metro, which was not running.

The Android WebSocket code previously only retried when `wsSignalingClient` became `null`. A half-open socket that never delivered `onclose` could retain a stale `✅ Connected` status forever. The backend already sends WebSocket protocol ping frames, but the JS app cannot observe the native pong lifecycle. It now sends a JSON `{ "type": "PING" }` every 25 seconds; the server sends `{ "type": "PONG" }`. After a sent PING remains unanswered for 75 seconds, Android invalidates and closes the stale socket, clears old P2P peers, and uses its existing authenticated retry (10 seconds). A paused/backgrounded Android JavaScript loop gets a fresh probe on resume instead of immediately triggering a false timeout. `socket.onerror` also invalidates the reference instead of relying solely on a missing `onclose` callback.
